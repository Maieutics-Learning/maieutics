What improved in the update

The tools index was expanded substantially and now gives a much fuller inventory of the tools.

The maximum absolute difference across eight paired seeds is one generation, and three inversion seeds favor the continued-student condition.

The result weakens the claim that generational turnover is necessary. The more defensible interpretation is that the staged hint-fading or teaching schedule may matter more than replacing the student at each generation.

Important research issue revealed by the update

The preregistered F-singlegen specification defined the continued-student condition as carrying both student weights and Adam optimizer state across generations. The full Phase 3 seed records instead describe carrying student weights while resetting Adam for each generation. The pilot runs do not establish that carrying and resetting optimizer state are equivalent. Therefore, the full-power experiment is not an exact test of the preregistered condition. This protocol deviation should be disclosed and either tested directly with an Adam-carry condition or reflected in a narrower conclusion: weight persistence under optimizer resets was sufficient under the tested conditions.

The raw F-singlegen runner and results were reportedly kept in scratch rather than included in the repository snapshot. Since this experiment changes the paper's central interpretation, the runner and raw results should be promoted into durable evidence storage and indexed in RESULTS_INDEX.md. The current index did not include F-singlegen.

The public-facing phrase “teaching compounds, not rots” may overstate what the new comparison shows. A more precise formulation would be: “The chained teaching procedure maintains successful performance across five generations, but a continued-weight student performs comparably, indicating that generational turnover is not necessary under the tested conditions.”

Assessment of student-generated tools

Overall assessment: the student-generated tools are worthwhile research-support prototypes. They are useful for organizing, exploring, critiquing, and diagnosing research work, but they should not yet be presented as validated general-purpose academic instruments or as substitutes for reproducible methods and independent expertise.

Memory tool

This appears to be the most practically valuable original tool. Its timestamped records, append-only corrections, conflict handling, explicit status labels (such as Observed, Verified, Hypothesis, and Retracted), and handoff/snapshot concepts are good foundations for research continuity. Issues include a documented allowPaths option that is not enforced by the search implementation; lexical substring search rather than semantic or recency-aware ranking; searches that may include scratch files despite the repository's durability policy; and a logger that does not enforce writes under src/. Read-modify-write operations are not atomic, and the single-writer rule is documented rather than enforced. The claimed end-to-end tests should be packaged with the tool. Verdict: a promising internal research memory system, not a formal research database.

Fresh-eyes tool

The structured critique workflow is a strong idea, especially the separation between conceptual criticism, re-analysis, and reproduction. Its central limitation is that multiple AI reviewers from the same provider or model family are correlated and do not constitute independent academic replication. Reviewer agreement is not proof. Reviewers also inherit the framing of the prompt and supplied artifacts. In particular, if several blind reviewers do not spontaneously raise an objection, that does not show the objection was imported or invalid; it only shows those reviewers did not raise it in that review. The experiment-specific fleet scripts should identify the current version clearly, with older versions archived or marked historical to avoid stale prompt contexts being run accidentally. Verdict: useful for structured criticism and red-teaming, not validation.

Rabbithole tool

This is a useful source-led exploration framework with bounded scout/fetch work per wave, primary-source orientation, explicit verdicts, branching, and checkpoints. Its main risk is unbounded exploration: the queue logic can continually open another wave, tangential exploration may be inserted by default, and the documentation describes a very long run that ended through user intervention rather than a native stopping rule. Add a finite default budget (waves, time, or cost), a clear deliverable, and an explicit stopping criterion; make tangential exploration optional. Verdict: useful exploratory workflow, but it needs stronger scope control.

Websearch tool

The DuckDuckGo HTML search parser is a lightweight discovery prototype, not a scholarly search system. A possible stale-result bug occurs when a fetch is unsuccessful but does not provide an error field: the code may continue and read an earlier scratch search page. It should fail closed whenever the fetch is not successful. Regex parsing of search-engine HTML is brittle; fixed output paths can collide during concurrent searches; and an omitted query appears to trigger an unrelated hard-coded default query. Add fixtures and validation, unique output paths, and an explicit missing-query error. Verdict: acceptable for exploratory discovery, not literature-search infrastructure.

IX diagnostic scripts

The IX scripts are focused, research-specific diagnostics rather than general-purpose interpretability tools. Positive features include artifact maps, fixed seeds, no retraining, validation gates, quarantined findings, saved JSON outputs, and explicit follow-up tests. However, they depend on scratch-only input blobs, so a fresh clone cannot reproduce the analyses. The repository should preserve the inputs, invocation instructions, and relevant source-code revision or hashes. The sign-flip analysis should be careful about pooled AUC potentially conflating between-brain differences with within-brain predictive performance; macro per-brain summaries and brain-clustered uncertainty estimates would strengthen it. The latch bootstrap's inference is conditional on the fixed evaluation lines and should be described that way. Verdict: careful exploratory diagnostics, not yet independently reproducible research packages.

Additional repository-level issues

The new adjudication document has a queued-actions list that is partly stale: some actions appear already completed in the current snapshot. Reconcile the list with current status.

The adjudication references review source files stored under scratch. Preserve the source review in a durable evidence/reviews location or record stable provenance and a hash.

The repository mixes skill/instruction documents, executable utilities, and one-off experimental orchestration scripts under the broad label “tools.” Label these categories clearly.

The project still lacks a one-command reproduction path for every headline result, and independent reproduction from tracked code has not been logged.

Cross-family transfer remains an open question.

Prioritized next steps

Resolve and document the F-singlegen optimizer-state protocol deviation; preserve the raw runner and results; add the experiment to RESULTS_INDEX.md.

Align the abstract and headline claims with the new finding that generational turnover was not necessary under the tested conditions.

Fix and test the memory and websearch edge cases; package automated tests and fixtures.

Give Rabbithole a finite default budget and stopping rule.

Clarify Fresh-eyes' evidential status, distinguish AI reviewer diversity from independent replication, and mark current versus historical fleet scripts.

Make IX diagnostics reproducible from a clean checkout by preserving their input blobs, commands, and source revision identifiers.

Prioritize reproducibility and a focused cross-family test over adding more tools.

Overall conclusion: the student-generated tools are generally decent and show thoughtful engineering and methodological awareness. Their value is strongest as research workflow support. The most important remaining work is not to build more tools, but to make the existing tools testable and the experiments reproducible, while being precise about what each result does and does not establish.
